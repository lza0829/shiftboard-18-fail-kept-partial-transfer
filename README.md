# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://127.0.0.1:5600 |
| 接口 | http://127.0.0.1:10600 |

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中）→ 完成交班整批过户 → 交班对账报告与清单/批次同源

## 失败闭（二选一，本仓选定第一种）

任一批次过户失败则整单失败，绝不出现「部分批次留在接班方在途 / 双方仍占进行中锁」。

- **选定的回滚形态：同一事务整单回滚（`SAVEPOINT transfer`）。**
  `BEGIN IMMEDIATE` 包住整单；过户与成功落档在 `SAVEPOINT transfer` 内，
  任一步骤异常即 `ROLLBACK TO SAVEPOINT transfer`，撤销全部归属变更，
  随后在同一事务内落失败单、按发起时班次快照恢复双方状态、写回滚证明并提交。
  因此提交后库里只可能是两种终态：全部过户的「已完成」，或归属原样 + 「失败」。
- **未备选**：按发起时归属快照显式回写（`handover_items.snapshot_owner_shift_id /
  snapshot_status`）。本仓保留该快照仅用于证明与核对，不作为回滚手段。

每次失败完成后落持久化回滚证明，可在「交班对账」与「交班办理」界面查看，也可只读查询：

```
GET /api/handovers/{id}/rollback-proof
```

证明字段（与批次表、交班单、对账报告同源，全部取自落库行）：

| 字段 | 含义 |
| --- | --- |
| `发起前归属指纹` | 对发起时固化的 `(批次, 业务键, 归属班次, 状态)` 快照做的 sha256 稳定哈希 |
| `发起前归属快照` | 逐批的发起前归属与状态 |
| `回滚后交班方在途批次` | 失败后 `batches` 表中交班方在途集合 |
| `回滚后交班方在途与发起清单一致` | 上述集合与发起清单逐项比对结果 |
| `归属已回滚到发起快照` / `状态已回到发起快照` | 失败后逐批与发起快照比对结果 |
| `锁释放结果` | 本单状态、全仓「进行中」单数、双方班次状态、是否可再次交班 |
| `回滚方式` / `事务回滚已执行` | 实际走的是事务回滚，还是过户前校验失败（未发生变更） |

## 界面约定

页面文案全部中文；入口：总览 / 班次 / 在途批次 / 交班办理 / 交班记录 / 交班对账。
失败单在「交班办理」结果区与「交班对账」详情区展示「回滚后交班方在途与发起清单一致」等证明字段。
